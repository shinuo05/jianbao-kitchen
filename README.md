# 煎包今天做什么 · HTML 家庭同步版

水蓝色与柔粉色的家庭菜谱网站。无需 Python：GitHub Pages 提供 HTML/CSS/JavaScript 页面，Supabase 提供登录、共享数据库和私有图片存储。

**交付的是待配置源码，尚未连接你的云端项目或发布。** 先打开「部署教程.html」，完成配置后才能登录使用。

## 功能

- 家庭成员邮箱/密码登录，不提供自助注册；数据库成员名单控制访问。
- 所有成员共享一套菜谱与冰箱食材；添加、编辑、删除菜谱，上传并压缩图片。
- 按荤菜、素菜、主食筛选；现有食材匹配；分别随机抽取三类菜。
- 页面打开且不处于编辑状态时每 15 秒检查更新，也可手动同步。编辑中暂缓刷新，版本冲突时拒绝覆盖。
- 导出含图片的 JSON，兼容旧版备份导入。导入会替换整个家庭数据，操作前请备份。
- 首次登录菜谱为空，可点击「导入示例」添加 6 道菜。

## 文件

- `index.html`、`style.css`：页面与主题。
- `app.js`：菜谱交互与食材匹配。
- `cloud.js`：登录、私有图片、共享保存与同步。
- `config.js`：只填 Project URL 和 Publishable key / anon key。
- `setup.sql`：在全新 Supabase 项目中执行一次，创建表、权限和存储桶。
- `seed.json`：可选的示例菜谱。
- `.nojekyll`：GitHub Pages 静态发布配置。

不要把数据库密码、service_role、secret key、个人备份、家人邮箱名单写入公开仓库。config.js 的公开 key 本来就允许进入前端，真实权限由数据库 RLS 和私有存储规则控制。

## 使用与限制

单个 Supabase 项目对应一个家庭。图片限制 5MB，界面会先缩小压缩。每次保存是整个家庭菜谱集合的原子更新，适合少量家庭成员，不是大规模多人系统。食材匹配不计算重量，调味料单独填写。菜单图片需手动补充菜名和食材，不含自动识图。

删除菜谱不会立即删除云端旧图片，避免破坏备份/正在编辑的内容；存储快满时先备份，再由管理员在 Storage 中清理确认不再使用的文件。

免费额度不是永久服务保证：Supabase 当前免费项目有 500MB 数据库、1GB 文件存储，低活跃约一周可能暂停，免费套餐不含自动备份。请定期使用网站「备份」功能，暂停后到 Supabase 控制台恢复。以 https://supabase.com/pricing 为准。

网页依赖 jsDelivr 提供 Supabase SDK，以及 Supabase 服务本身；家人使用前应在各自网络测试访问。免费 GitHub Pages 通常使用公开仓库，代码公开不等于菜谱公开。

## 上线验收（配置后执行）

1. 未登录打开网站，只显示登录页。
2. 家人 A 登录并添加一道带照片的菜和食材。
3. 家人 B 在另一个浏览器登录，等待 15 秒或点击同步，应看到同一份内容。
4. A、B 同时打开同一道菜，A 保存后 B 再保存，应出现冲突提示，A 的修改不能被覆盖。
5. 导出备份，检查包含图片；在确认后导入，应恢复菜谱和食材。
6. 在 Authentication 创建一个测试账号但不加入 family_members，登录后必须不能读写菜谱或访问图片。
7. 从 family_members 移除测试成员，再同步，应失去数据库与图片访问权。已经下载到浏览器的内容无法远程收回。
8. 退出登录后页面隐藏家庭数据；刷新仍需要登录。

交付时进行了 JavaScript 语法与模拟云端同步逻辑检查；真实登录、SQL 执行、跨设备同步需创建你的项目后按上述步骤验收。
